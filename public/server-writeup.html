HTTP Server in C

COMS 3157 Advanced Programming · private repo · you are reading this off my server

An iterative TCP web server built on the raw socket API — socket(), bind(), listen(), accept() — serving static files and query results from a database also written in C. Requests are handled to completion one at a time; the database opens at startup, so no query pays for a fresh handshake.

The code has to stay private while the assignment is in use, so this page is the artifact instead. Every byte of it came off disk and through a socket my server owns, and the log on the right is that server recording you reading it.

Request handling

Each connection is read until the request line is complete, then validated before anything touches the filesystem: the method, the HTTP version, and a URI that must begin with /. Anything malformed gets a 400 and never becomes a path lookup.

Valid paths resolve against the document root. A missing file is a 404; a file the process cannot read is a 403 — distinguished by errno, not by guessing. Every response, including the failures, is logged with the client IP.

The database

The database parses a binary file with fread into a linked list of records held in memory. Searching walks the list with a comparison callback passed in by the caller, so traversal is decoupled from business logic, and a matching free callback keeps the record lifecycle leak-free.

What is in it: this site's own content — one fixed-width record per project and publication. Query one and the server walks the list and writes the matching row back as HTML.

What it taught me

Almost all of the work was defensive. The happy path — parse, open, write — was a day; the rest was every way a client can be wrong, and making sure a bad request costs the server a log line instead of a crash.
