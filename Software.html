AI Claim Detection

Github: Claim_Detection

Overview

This project was completed as a takehome portion of a technical interview proccess. I was tasked with creating a claim detection model that could be used to identify whether an inputed string was a claim or not. In order to solve this problem I decided to fine tune a lightweight BERT model on two sepreate datasets. After training the model I wrapped it in a simple Flask and FastAPi web server and created a simple HTML/CSS/JS frontend to interact with the model. All of this was dockerized for easy deployment.

Fine-Tuning

Because I was training this model locally I selected a lightweight BERT model (distilBERT) to fine tune. When fine tuning the model I used a combination of two datasets. The first dataset was the "ClaimBuster" dataset which contains sentences from political debates that have been labeled as claims or not claims. Becasue this data was unequally weighted towards non-claims I also incorporated a second dataset called "FeverClaims") consists of 185,445 claims generated by altering sentences extracted from Wikipedia and subsequently verified without knowledge of the sentence they were derived from. These datasets were combined in a way that ensured an equal weighting of claims and non-claims and then used to fine tune the distilBERT model. After fine-tuning the model achieved an accuracy of around 90% on a held-out test set.

Web Server and Frontend

After the weights were trained I wrapped the model in a simple Flask and FastAPI web server. The web server exposes a single endpoint that takes in a string and returns whether the model predicts it to be a claim or not. This endpoint is protected by string length validation and a rate limiter to prevent abuse. After creating the endpoint I also create a simple HTML/CSS/JS frontend that allows users to input a string and see the model's prediction in real time.

Testing

To ensure that the model could possibly be used in a production environment I also used Locust to create a simple load test for the web server. This load test simulates multiple users sending requests to the server at the same time and measures the response time and error rate. The results of the load test showed that the server was able to handle a high volume of requests with a low error rate and an average response time of around 200ms.
