AI Claim Detection

Github: Claim_Detection

Overview

This project was completed as a takehome portion of a technical interview proccess. I was tasked with creating a claim detection model that could be used to identify whether an inputed string was a claim or not. In order to solve this problem I decided to fine tune a lightweight BERT model on two sepreate datasets. After training the model I wrapped it in a simple Flask and FastAPi web server and created a simple HTML/CSS/JS frontend to interact with the model. All of this was dockerized for easy deployment.

Fine-Tuning

Because I was training this model locally I selected a lightweight BERT model (distilBERT) to fine tune. When fine tuning the model I used a combination of two datasets. The first dataset was the "ClaimBuster" dataset which contains sentences from political debates that have been labeled as claims or not claims. Becasue this data was unequally weighted towards non-claims I also incorporated a second dataset called "FeverClaims") consists of 185,445 claims generated by altering sentences extracted from Wikipedia and subsequently verified without knowledge of the sentence they were derived from. These datasets were combined in a way that ensured an equal weighting of claims and non-claims and then used to fine tune the distilBERT model. After fine-tuning the model achieved an accuracy of around 90% on a held-out test set.

Web Server and Frontend

After the weights were trained I wrapped the model in a simple Flask and FastAPI web server. The web server exposes a single endpoint that takes in a string and returns whether the model predicts it to be a claim or not. This endpoint is protected by string length validation and a rate limiter to prevent abuse. After creating the endpoint I also create a simple HTML/CSS/JS frontend that allows users to input a string and see the model's prediction in real time.

Testing

To ensure that the model could possibly be used in a production environment I also used Locust to create a simple load test for the web server. This load test simulates multiple users sending requests to the server at the same time and measures the response time and error rate. The results of the load test showed that the server was able to handle a high volume of requests with a low error rate and an average response time of around 200ms.

Custom C-based Web Server

Github: This code is private due to its use as a homework assignment.

Overview

This project was completed as a cumulative project for COMS 3157 (Advanced Programming) at Columbia University. The goal of the project was to create a custom HTTP web server in C that could handle multiple concurrent connections and serve static files along with a sample database we also developed in class. The server was designed to be simple and efficient, and it was implemented using the socket API and basic C to handle multiple users and serve files from a specified directory. The server also included basic error handling and logging capabilities to ensure that it could be used in a production environment.

System Architecture & Design

This project was developed entirley in C using the socket API. It is a iterative TCP server that listens for incoming connections on a specified port. Unlike a multithreaded server his architecture processes one HTTP request to completion before moving to the next in the queue. I used basic socket(), bind(), and listen() calls to handel the TCP lifecycle. Before the server started up it also connected to a database we also developed in C during the class. This connetion was made beforehand to minimizes latency by avoiding a new handshake for every user query. This design helped us mirror a classic 3-teir architecture with the web server acting as the presentation layer, the database acting as the data layer, and the server logic acting as the application layer.

Database Integration

The database we developed for this parses a binary database file using fread and dynamically populates a custom linked list with MdbRec structures, ensuring the dataset is memory-resident for high-speed retrieval. The core search logic leverages higher-order functions and function pointers, passing a callback to a generic traverseList routine that performs case-sensitive substring matching via strstr. This architecture effectively decouples the data traversal from the business logic, while a final cleanup pass with a freeData callback ensures a leak-free lifecycle, a critical requirement for systems-level programming.

Error Handling

To ensure that our server was resilant to user inputs I implemented robust error handeling that covered a wide range of potential issues. This included handling malformed HTTP requests, the server takes the inputed request and parses it to ensure that it follows the correct HTTP format. It matches to ensure the HTTP version is correct, that the URI starts with a / among other simmalar checks. When any of these errors are discovered the server responds with the appropriate HTTP error code and message. I also implemented error handling for file not found errors, permission errors, and other common issues that could arise when serving static files. All errors are also logged to the terminal with the IP address of the user for debugging purposes.

Physics-based Free Throw Simulation

Github: Private due to academic integrity policies

Overview

This project was completed as a cumulative project for my computer simulation class at Washington & Jefferson College. The goal of the project was to create a physics-based simulation of a basketball free throw loosly based off of this paper "A physics-based model of basketball free throw trajectories". Our simulation was wrapped in a frontend that allowed users to input the initial conditions of the free throw (angle, velocity, etc.) and see a visual representation of the trajectory of the ball. The simulation was designed to be as accurate as possible while still being computationally efficient, and it included factors such as air resistance and spin to create a more realistic simulation. The project was completed in Python using libraries such as NumPy and Matplotlib for the physics calculations and visualization.

Physics

This project simulates projectile motion by modeling a ball's trajectory in a two-dimensional plane, assuming linear, front-facing shots with negligible lateral (Z-axis) deviation. The system accounts for standard environmental constants on Earth, such as gravitational acceleration (g = −9.81 m/s2) and air density (ρ = 1.225 kg/m3)—while calculating dynamic trajectory paths based on variable release velocities, angles, and initial ball dimensions. Aerodynamic drag is incorporated via the drag equation (FD = ½ρv2CDA) for translational movement, though the ball's initial backspin (ω) is assumed to remain constant through the flight due to minimal atmospheric friction. To keep the simulation universally applicable across different targets (like basketball hoops or trash cans), backboard reflections and complex rim physics are omitted; instead, a geometric clearance allowance (sin(α) = r / (2R - r)) determines a successful score.

Parameters

The user interfave allows for the input of several paramaters that can be adjusted in between shots. The main paramaters that one would change shot to shot are on the front page and include the release angle, release velocity, your height and backspin. There are also several other paramters relating to the enviorment and the ball that can be changed in a seperate settings page. You can choose new destnations to shoot the ball such as the moon or underwater which changes the enviormental constants to match those destnations. You can also change the height, size and distance away from the hoop you are. Finally you can change the size and mass of the ball which allows you to have fun with the physics and see how different balls would fly in differnet locations.
